Where each responsibility lives

Host owns the shell

Mount one provider and one persistent Panel. Pass a scoped writer to the selected Journey and a reader to the Panel. Switching menus closes the old scope.

Journey owns the feature

Publish screen context, a named tool with a handler, and a card mount function. The Journey renders its screen and its cards with its own React DOM.

Panel owns the AI

Subscribe to the writer’s published snapshot, bind it to CopilotKit, run the agent, and place its replies and tool results inside the existing chat UI.

Share the React runtime and CopilotKit provider context between the Host and Panel. Each Journey can ship its own React and React DOM pair and adopt the versioned JS contract on its own release schedule.

Pass the API to both remotes Host.jsx
The Host calls the selected remote’s mount(container, api) and renders the Panel as a React child of the provider. Only the Journey slot is keyed by menu selection. The React 19 Journey implements the same mount contract with createRoot and root.unmount.
Host.jsx
import React, { lazy, Suspense, useLayoutEffect, useRef, useState } from 'react';
import { CopilotKitProvider } from '@copilotkit/react-core/v2';
import { createJourneyBridge } from './bridge.mjs';

// Module Federation remote aliases, configured at build time.
const Panel = lazy(() => import('aiPanel/Panel'));
const journeys = {
  Orders: () => import('orders/mount'),
  Payments: () => import('payments/mount')
};

function JourneySlot({ name, bridge }) {
  const container = useRef(null);
  const [error, setError] = useState('');
  useLayoutEffect(() => {
    const scope = bridge.open(name);
    let disposed = false;
    let unmount;
    journeys[name]().then(remote => {
      if (!disposed) unmount = remote.mount(container.current, scope.api);
    }).catch(err => {
      if (!disposed) {
        scope.close();
        setError(String(err));
      }
    });
    return () => {
      disposed = true;
      scope.close();
      unmount?.();
    };
  }, [bridge, name]);
  return <section>{error && <p role="alert">{error}</p>}<div ref={container}/></section>;
}

export default function Host({ agentConfig }) {
  const [name, select] = useState('Orders');
  const [bridge] = useState(createJourneyBridge);
  return <CopilotKitProvider {...agentConfig}>
    <nav>{Object.keys(journeys).map(item =>
      <button key={item} onClick={() => select(item)}>{item}</button>
    )}</nav>
    <main className="two-columns">
      <JourneySlot key={name} name={name} bridge={bridge}/>
      <Suspense fallback="Loading assistant…">
        <Panel reader={bridge.reader}/>
      </Suspense>
    </main>
  </CopilotKitProvider>;
}


Define the JavaScript contract bridge.mjs
open() gives the active Journey a writer. The Panel subscribes to the reader and can retrieve the latest snapshot even if it loads later. close() invalidates old handlers and signals cancellation. An asynchronous Journey handler can pass that signal to fetch.
bridge.mjs
// Host-owned. One instance per application shell.
export function createJourneyBridge() {
  const listeners = new Set();
  let active = null;
  let nextId = 0;

  function publish(snapshot) {
    active = snapshot;
    for (const notify of listeners) notify();
  }

  const reader = {
    getSnapshot: () => active,
    subscribe(notify) {
      listeners.add(notify);
      return () => listeners.delete(notify);
    }
  };

  function open(journey) {
    const id = ++nextId;
    const controller = new AbortController();
    const current = () => active?.id === id && !controller.signal.aborted;
    function update(patch) {
      if (current()) publish({ ...active, ...patch });
    }
    function add(group, name, value) {
      if (!current()) return;
      if (Object.hasOwn(active[group], name)) {
        throw new Error('Duplicate registration: ' + name);
      }
      update({ [group]: { ...active[group], [name]: value } });
    }

    publish({ id, journey, context: {}, tools: {}, components: {} });
    const api = {
      version: 1,
      setContext: value => update({ context: structuredClone(value) }),
      registerComponent: (name, mount) => add('components', name, mount),
      registerTool(tool) {
        add('tools', tool.name, {
          ...tool,
          async execute(args) {
            if (!current()) throw new Error('Journey has changed');
            const result = await tool.execute(args, controller.signal);
            if (!current()) throw new Error('Journey has changed');
            return result;
          }
        });
      }
    };
    function close() {
      controller.abort();
      if (active?.id === id) publish(null);
    }
    return { api, close };
  }
  return { reader, open };
}


Register context, a tool, and a card orders.jsx
The React 16 example contributes a real OrderCard via a mount function. Only the DOM node and plain order data cross the boundary. Register the card before its tool and use a unique, stable tool name for each Journey capability.
orders.jsx
// The Orders remote resolves both imports to its own React 16 runtime.
import React from 'react';
import ReactDOM from 'react-dom';

const orders = [
  { id: 'ORD-1042', status: 'In transit' },
  { id: 'ORD-1043', status: 'Processing' }
];

function OrderCard({ order }) {
  return <article><strong>{order.id}</strong><p>{order.status}</p></article>;
}

export function mount(container, api) {
  if (api.version !== 1) throw new Error('Unsupported Journey API');
  let selected = orders[0];

  // The Panel supplies a DOM node. Orders owns this small React root.
  api.registerComponent('orders.card', (node, order) => {
    ReactDOM.render(<OrderCard order={order}/>, node);
    return () => ReactDOM.unmountComponentAtNode(node);
  });

  api.registerTool({
    name: 'orders_lookup',
    description: 'Look up an order visible in the active Orders journey.',
    inputSchema: {
      type: 'object', properties: { id: { type: 'string' } },
      required: ['id'], additionalProperties: false
    },
    component: 'orders.card',
    async execute({ id }) {
      const order = orders.find(item => item.id === id);
      if (!order) throw new Error('Order is unavailable');
      return order; // JSON data for both the agent and the card.
    }
  });

  function select(order) {
    selected = order;
    api.setContext({ selectedOrderId: selected.id });
    ReactDOM.render(<section>
      <h2>Orders</h2>
      {orders.map(item =>
        <button key={item.id} aria-pressed={item.id === selected.id}
          onClick={() => select(item)}>{item.id}</button>
      )}
    </section>, container);
  }
  select(selected);
  return () => ReactDOM.unmountComponentAtNode(container);
}


Translate registrations into CopilotKit Bindings.jsx
This code belongs to the AI Panel. Each tool gets its own binding component so the number of hooks within any component stays constant. The example uses the Zod 4 build that exports z.fromJSONSchema; pin and test this experimental conversion against the JSON Schema subset your teams support.
Bindings.jsx
import React, { useEffect, useMemo, useRef } from 'react';
import { useAgentContext, useFrontendTool } from '@copilotkit/react-core/v2';
import { z } from 'zod';

function JourneyCard({ mount, result }) {
  const node = useRef(null);
  useEffect(() => {
    // Called only for a successful, completed tool result.
    return mount(node.current, JSON.parse(result));
  }, [mount, result]);
  return <div ref={node}/>;
}

function ToolBinding({ tool, mount }) {
  const schema = useMemo(() => z.fromJSONSchema(tool.inputSchema), [tool]);
  useFrontendTool({
    name: tool.name,
    description: tool.description,
    parameters: schema,
    handler: async args => {
      try {
        const data = await tool.execute(schema.parse(args));
        return JSON.stringify({ ok: true, data });
      } catch (err) {
        return JSON.stringify({ ok: false, message: String(err.message || err) });
      }
    },
    render: ({ result }) => {
      if (result == null) return <small>Looking up…</small>;
      let reply;
      try { reply = JSON.parse(result); }
      catch { return <small>{String(result)}</small>; }
      if (!reply?.ok) return <small>{reply?.message || 'Lookup unavailable'}</small>;
      return mount
        ? <JourneyCard mount={mount} result={JSON.stringify(reply.data)}/>
        : <pre>{JSON.stringify(reply.data, null, 2)}</pre>;
    }
  }, [tool.name]); // Registration is immutable for this Journey session.
  return null;
}

export function Bindings({ snapshot }) {
  useAgentContext({ description: 'Active ' + snapshot.journey + ' screen',
                    value: snapshot.context });
  return Object.values(snapshot.tools).map(tool =>
    <ToolBinding key={tool.name} tool={tool}
      mount={snapshot.components[tool.component]}/>
  );
}


Read context, invoke tools, and render chat Panel.jsx
The panel reads screen.context locally and uses agent.messages for conversation history. Send starts an agent run. Show selected order calls a browser tool directly. Both paths use the same tool renderer. The transcript example covers text and tool messages.
Panel.jsx
import React, { Fragment, useRef, useState, useSyncExternalStore } from 'react';
import { useAgent, useCopilotKit, useRenderToolCall } from '@copilotkit/react-core/v2';
import { Bindings } from './Bindings';

export default function Panel({ reader }) {
  const screen = useSyncExternalStore(reader.subscribe, reader.getSnapshot);
  const { agent, isReady } = useAgent({ agentId: 'default' });
  const { copilotkit } = useCopilotKit();
  const renderToolCall = useRenderToolCall();
  const [draft, setDraft] = useState('');
  const [error, setError] = useState('');
  const [busy, setBusy] = useState(false);
  const locked = useRef(false);

  async function act(operation) {
    if (!isReady || locked.current || agent.isRunning) return;
    locked.current = true;
    setBusy(true);
    setError('');
    try { await operation(); }
    catch (err) { setError(String(err.message || err)); }
    finally { locked.current = false; setBusy(false); }
  }

  function send(event) {
    event.preventDefault();
    const content = draft.trim();
    if (!content) return;
    return act(async () => {
      agent.addMessage({ id: crypto.randomUUID(), role: 'user', content });
      setDraft('');
      await copilotkit.runAgent({ agent });
    });
  }

  function lookup() {
    return act(async () => {
      const { error } = await copilotkit.runTool({
        agentId: 'default', name: 'orders_lookup',
        parameters: { id: screen.context.selectedOrderId }
      });
      if (error) throw new Error(String(error));
    });
  }

  const messages = agent.messages;
  const results = new Map(messages.filter(m => m.role === 'tool')
    .map(m => [m.toolCallId, m]));
  const disabled = !isReady || busy || agent.isRunning;
  return <aside>
    {screen && <Bindings key={screen.id} snapshot={screen}/>}
    <header>{screen?.journey} · {screen?.context.selectedOrderId}</header>
    {messages.filter(m => ['assistant', 'user'].includes(m.role)).map(m =>
      <article key={m.id}>
        {typeof m.content === 'string' && <p>{m.content}</p>}
        {m.toolCalls?.map(call => {
          const toolMessage = results.get(call.id);
          return <Fragment key={call.id}>
            {renderToolCall({ toolCall: call, toolMessage }) ??
              <pre>{String(toolMessage?.content ?? call.function.name)}</pre>}
          </Fragment>;
        })}
      </article>
    )}
    {screen?.tools.orders_lookup && screen.context.selectedOrderId &&
      <button disabled={disabled} onClick={lookup}>Show selected order</button>}
    <form onSubmit={send}>
      <input aria-label="Message" value={draft}
        onChange={e => setDraft(e.target.value)}/>
      <button disabled={disabled || !draft.trim()}>Send</button>
    </form>
    {error && <p role="alert">{error}</p>}
  </aside>;
}




Module Federation setup
Expose ./Panel from the AI remote and ./mount from each Journey remote. Render the Panel as a component of the Host. Configure Host and Panel to resolve the same instances of react, react-dom, and @copilotkit/react-core/v2, including the React subpath imports your build emits. Keep each isolated Journey’s React imports local to its bundle or in a separate share scope.


Connect your WebSocket
Let the AI team supply the provider configuration. For a browser-side adapter, pass agentConfig={{ selfManagedAgents: { default: socketAgent } }} to the Host. The adapter implements the AG-UI agent interface and forwards run input, including messages, context, tools, thread ID, and run ID. It translates incoming text, tool-call, completion, and error frames into AG-UI events. CopilotKit executes registered browser tools and can continue the run with their results.
The sample assumes a configured agent named default. Implement the adapter against your backend’s actual frame format. A text-only socket needs support for structured tool calls and results.
