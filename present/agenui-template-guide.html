Template Stack

Everything needed for a company-standard React module.

AgenUI keeps the visual system consistent, while the supporting layers keep page state, wording, API communication, navigation, and shared session data predictable across the project.

AgenUI Component Library

Prebuilt components that already match the company's design language, spacing, colors, and interaction patterns.

Zustand View Models

Small page-focused stores for loading state, form state, selected records, filters, and UI decisions.

i18n Locale Wording

Centralized wording keys so pages can switch language without scattering copy through components.

RxJS API Client

Observable-based request pipelines for API calls, cancellation, retry, error mapping, and response transformation.

Controller Container

A page-level orchestration layer for navigation, route transitions, data loading, and passing view state into UI.

Shared Session Storage

Project-wide access to session-scoped values such as user context, active workspace, tokens, and temporary preferences.

Architecture

A clear path from page interaction to backend data.

The recommended flow keeps UI components presentational, moves page decisions into the controller and view model store, and isolates network behavior inside RxJS API clients.

AgenUI Components

Controller Container

Owns route behavior, page composition, event handlers, and navigation decisions.

VM

Zustand Store

Stores view data such as filters, selected rows, loading flags, errors, and derived page state.

API

RxJS Client

Calls backend APIs through typed observable pipelines and normalizes success or failure responses.

Shared services such as i18n and session storage are available across layers, but components should consume them through hooks, controller props, or view model selectors where possible.

Project Structure

A suggested folder map for the template.

Adjust names to match your repository, but keep each responsibility easy to find.

src/components/
Reusable AgenUI-based components shared across pages.
src/pages/
Page screens composed by controller containers and presentational UI.
src/controllers/
Navigation, page orchestration, route params, and lifecycle behavior.
src/stores/
Zustand view model stores scoped by feature or page.
src/api/
RxJS API clients, request types, response mappers, and endpoint modules.
src/locales/
i18n wording keys grouped by language and feature namespace.
src/session/
Shared session storage helpers, keys, serializers, and user context utilities.
Recipes

Use these patterns when adding a new feature.

The goal is consistency: each feature should look, read, navigate, store state, and call APIs in the same way.

Controller container pattern 
export function UserListController() {
  const { t } = useTranslation();
  const navigate = useNavigation();
  const { users, isLoading, loadUsers, selectUser } = useUserListStore();

  useEffect(() => {
    loadUsers();
  }, [loadUsers]);

  return (
    <UserListPage
      title={t("users.title")}
      users={users}
      loading={isLoading}
      onCreate={() => navigate.to("/users/create")}
      onSelect={selectUser}
    />
  );
}
Zustand view model store 
export const useUserListStore = create((set, get) => ({
  users: [],
  selectedUserId: null,
  isLoading: false,
  error: null,

  selectUser: (userId) => set({ selectedUserId: userId }),

  loadUsers: () => {
    set({ isLoading: true, error: null });

    userApi.listUsers().subscribe({
      next: (users) => set({ users, isLoading: false }),
      error: (error) => set({ error, isLoading: false }),
    });
  },
}));
RxJS API client 
export const userApi = {
  listUsers() {
    return apiClient.get("/users").pipe(
      map((response) => response.data.items),
      catchError((error) => throwError(() => normalizeApiError(error)))
    );
  },

  createUser(payload) {
    return apiClient.post("/users", payload).pipe(
      map((response) => response.data),
      catchError((error) => throwError(() => normalizeApiError(error)))
    );
  },
};

Shared session storage 
const SESSION_KEYS = {
  userContext: "agenui:user-context",
  activeWorkspace: "agenui:active-workspace",
};

export function saveSessionValue(key, value) {
  sessionStorage.setItem(key, JSON.stringify(value));
}

export function readSessionValue(key) {
  const value = sessionStorage.getItem(key);
  return value ? JSON.parse(value) : null;
}
Guidelines

Keep new work aligned with the template.

These conventions help teams build features that feel native to the company product ecosystem.

UI and Components

  • Prefer AgenUI components before creating custom UI.
  • Keep page components presentational and pass behavior through props.
  • Use the company's existing spacing, color, table, form, and modal patterns.

State and View Models

  • Use Zustand for page-level view data and interaction state.
  • Keep API response shape mapping out of visual components.
  • Expose selectors or small actions instead of leaking large store objects.

API Client

  • Put endpoint calls in RxJS client modules by feature domain.
  • Normalize backend errors before they reach the UI.
  • Use observable operators for mapping, retry, cancellation, and composition.

Locale and Session

  • Use i18n keys for visible wording, including empty and error states.
  • Store only session-scoped data in session storage.
  • Define session keys centrally so values remain discoverable and consistent.
