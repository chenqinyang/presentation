Host Shell

The Host UI owns the product frame.

The Host is the stable application container. It decides what page is active, loads Micro UIs through Rsbuild Module Federation, supplies shared providers, enforces route guards, and chooses whether a Micro UI mounts through shared React or the bridge-react legacy path.

Layout and Navigation

Header, sidebar, route registry, breadcrumbs, page titles, and product-level transitions.

Shared Providers

Theme, locale, session, user profile, permissions, React compatibility, and application configuration.

Guardrails

Authentication checks, permission gates, unavailable remote fallbacks, version mismatch handling, and error boundaries.

Micro Composition

Micro UIs render inside controlled mount areas.

The Host decides where a Micro UI can appear. The Micro UI owns the feature workflow inside that area, while the Host keeps global behavior consistent. Runtime loading is handled through Rsbuild Module Federation, then normalized through the Host mount contract.

Rsbuild Module Federation

The Host loads Micro UIs as federated remotes.

Rsbuild Module Federation gives the Host a runtime loading model: each Micro UI publishes a remote entry and exposed mount module. The Host resolves the remote, checks compatibility metadata, then mounts it inside the correct page container.

Host Loader Responsibilities

  • Resolve remote entry URL by route, environment, tenant, or feature flag.
  • Load the exposed module and validate required Host and React compatibility.
  • Provide shared dependencies for modern Micro UIs where versions match.
  • Choose bridge-react for legacy React 16.2 Micro UIs before mounting.

Micro UI Remote Responsibilities

  • Publish a stable remote entry and a small exposed mount module.
  • Declare framework mode: shared React or legacy bridge-react.
  • Keep internal feature state private and expose only contract-level events.
  • Build modern Micro UIs with the AgenUI template when using the Host React version.

async function mountMicroUi(definition, container, hostContext) {
  const remote = await loadFederatedRemote(definition);

  if (definition.reactMode === "legacy-react-16.2") {
    return mountWithBridgeReact(remote, container, hostContext);
  }

  return remote.mount(container, hostContext);
}
React Compatibility

Most Micro UIs share the Host React version; legacy React 16.2 uses bridge-react.

Modern Micro UIs are easiest to operate because they use the same React JS version as the Host UI. Older React 16.2 Micro UIs should not share React internals with the Host; they need a bridge layer that mounts them as isolated islands with plain-data contracts.

Modern Shared React Path

  • Use Host-compatible React and ReactDOM versions through shared federation dependencies.
  • Consume Host theme, locale, session, permissions, and navigation through typed context props.
  • Use the AgenUI template stack for consistent UI, store, API, wording, and controller patterns.
  • Mount directly through the remote module's standard mount/unmount contract.

Legacy React 16.2 Bridge Path

  • Mount through bridge-react so React 16.2 can coexist with the Host React runtime.
  • Pass only serializable props, callbacks, event handlers, and normalized context data.
  • Avoid sharing Host React context, hooks, component instances, or renderer internals.
  • Wrap the legacy island with Host-level loading, error boundary, cleanup, and retry behavior.

Template Micro UIs

Modern Micro UIs use the AgenUI React template.

When a Micro UI uses the same React version as the Host, it follows the template foundation you described earlier: AgenUI for company-standard components, Zustand as the view model store, i18n for wording, RxJS for API clients, a Controller container for page navigation, and session storage helpers for shared project context.

AgenUI Components

Micro UI screens match the company design system without re-creating visual rules.

Zustand View Model

Feature state remains inside the Micro UI while Host context is passed through the contract.

RxJS API Client

Feature APIs stay observable-based with consistent mapping, retry, and error normalization.

i18n Wording

Micro UI wording is namespaced but still respects Host locale and formatting context.

Controller Container

Page navigation and feature orchestration are coordinated with the Host navigator.

Session Helpers

Session data is read through the Host contract or approved shared session helpers.

Recommended default

New Micro UIs should use the modern template path unless there is a clear legacy constraint. React 16.2 Micro UIs should be treated as compatibility islands, not as the normal pattern.

Shared Context

Shared services come from the Host, not from hidden coupling.

Micro UIs should consume shared data through explicit providers, hooks, or contract props. This keeps each feature independent while preserving one product experience.

Context to Share

  • Session user, active tenant, workspace, and access token reference.
  • Locale, date formatting, timezone, currency, and wording namespace.
  • Theme tokens, design system version, and company UI configuration.
  • Permission rules, feature flags, app-level configuration, and React compatibility mode.

Context to Avoid Sharing

  • Micro UI internal store state that should remain feature-owned.
  • Private implementation details such as component refs or internal routes.
  • Mutable global objects without versioning or cleanup rules.
  • Backend response shapes before they are normalized by an API boundary.
  • Host React context or hooks inside React 16.2 bridge-react islands.

Navigation

The Host owns the route map; Micro UIs own feature intent.

Let Micro UIs request navigation through a Host navigator. That keeps browser history, route guards, analytics, deep links, and federated remote loading centralized.

Host Responsibilities

  • Define top-level routes and Micro UI mount points.
  • Validate permissions before loading a Micro UI.
  • Own deep-link parsing, redirects, and not-found routes.
  • Resolve the Rsbuild remote and compatibility mode for each route.

Micro UI Responsibilities

  • Request navigation through the provided Host navigator.
  • Keep internal tabs and local feature state inside the mount area.
  • Expose route needs as contract requirements, not hidden assumptions.
  • Use template Controller containers for modern Micro UI page orchestration.
Communication

Use explicit boundaries for data and events.

The Host and Micro UIs can collaborate through event channels, callbacks, shared context, and API clients. The important rule is that communication is named and versioned, especially across bridge-react legacy islands.

Ownership

Clear ownership lets teams move independently.

The architecture should make it obvious who owns each surface, contract, and release decision.

Platform Team

Owns Host Shell, Rsbuild federation runtime, route registry, providers, bridge-react policy, and shared design system setup.

Feature Team

Owns Micro UI feature screens, local state, feature API usage, template adoption, tests, and release notes.

Shared Review

Versioned contracts, React compatibility mode, remote manifest changes, observability, and rollout strategy are reviewed together.

Failure Handling

The Host protects the product when a Micro UI fails.

Runtime composition needs graceful states. A missing remote, failed permission check, slow load, React version mismatch, bridge-react mount failure, or runtime error should never break the full Host UI.

Host fallback states

Loading, remote unavailable, permission denied, React version mismatch, bridge mount failure, and retryable runtime error states should be designed in the Host Shell.

Micro UI recovery

Micro UIs should expose cleanup behavior, cancel in-flight work on unmount, and report user-safe error messages through the contract. Legacy React 16.2 islands should also clean up bridge-react mounts.

Review Checklist

Use this before adding a new Micro UI.

A Micro UI is ready to integrate when the Host can load it, guard it, pass context, choose the correct React integration path, communicate with it, and recover from failure.

Host Integration

  • Route, mount slot, fallback UI, permissions, and analytics are defined.
  • Shared session, locale, theme, and feature flags are passed explicitly.
  • Rsbuild remote loading, React compatibility checks, unavailable remote, and runtime error states are tested.

Micro UI Readiness

  • Manifest, exposed module, mount props, and events are documented.
  • Internal state is isolated from Host and other Micro UIs.
  • Modern Micro UIs use the AgenUI template when sharing Host React.
  • React 16.2 Micro UIs declare bridge-react mode, cleanup, and release ownership clearly.
