    SurfaceStateMeaning
    Inspect recovery and release checks

    1

    Build separately; test together.

    Props, callbacks, route ownership and tested shared-library versions are application contracts. Module Federation supplies code composition; it does not invent or validate your business contract.

    2

    Boundary reset is not an import retry.

    React.lazy caches its Promise. A rejected import remains rejected for that lazy component. Use a fresh page after recovery, or design a new loader identity plus deliberate runtime recovery.

    3

    Rollback changes future selection.

    This example pins URLs in host build configuration. Changing a pin needs a host rebuild and deployment. Existing tabs can retain old modules; no instantaneous in-memory replacement is promised.

    REUSE THIS PATTERN

    Make release ownership visible.

    Use this template for platform reviews, microfrontend rollout plans, incident drills, or team onboarding. It is a design explainer, not a working React deployment.

    1. Replace teams and artifacts

    Show who builds the host and each remote. Keep release manifests, remote entries and hashed assets together under immutable version paths.

    2. Choose how selection works

    The shown map is compiled into the host. A dynamic registry is optional application infrastructure; it is not an automatic Federation feature.

    3. Name the failure boundary

    Keep local shell boot separate from route code. Explain pending code, rejected imports, render errors and journey-owned API errors individually.

    4. Distinguish fresh and open tabs

    State when a new host configuration takes effect. Keep a retained-module lane so rollback cannot be mistaken for a live module swap.
