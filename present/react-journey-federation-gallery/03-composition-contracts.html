THE TYPE CONTRACT

A small, explicit surface between teams.

Illustrative TypeScript · a team convention, not a Module Federation API.

type JourneyId = "onboarding" | "checkout" | "account";

type JourneyProps = {
  basePath: string;
  locale: "en-US" | "en-GB";
  theme: "light" | "dark";
  session: { userId: string; displayName: string };
  navigate: (to: string) => void;
  onComplete: (event: {
    journey: JourneyId;
    resultId: string;
  }) => void;
  apiClient: AuthenticatedApiClient;
};

// The remote exports a component, not a new root.
export default function Journey(props: JourneyProps) {
  // Handle child routes beneath props.basePath.
  // Save via apiClient; report success via onComplete.
  return <JourneyView {...props} />;
}
AuthenticatedApiClient and JourneyView are application-defined types/components. This excerpt is a contract sketch, not a complete deployment. The backend still authorizes every business operation.
ROUTING & INTEGRATION RULES

One browser history. Clear responsibility.

Federation resolves code; the Host controls how it joins the application.

01

The Host owns top-level routes.

/onboarding/*, /checkout/*, and /account/* select known lazy loaders. Journeys handle child routes beneath their basePath and request navigation through the Host. Do not create a competing top-level router or history.

02

Remote entry points expose UI.

Each Rsbuild build uses pluginReact and pluginModuleFederation from @module-federation/rsbuild-plugin, exposing ./Journey. The Host mounts its default React export. A separate standalone development entry may create its own root.

03

Shared dependencies need a tested policy.

Align tested React / ReactDOM versions and singleton settings. Audit package subpath imports. Use shareStrategy: 'loaded-first' for this gallery’s route-driven loading model. Sharing dependencies does not automatically share stores or context module identity.

04

Contain styling and handle domain failures.

Use CSS Modules or scoped styling with shared design tokens. Global CSS can still collide. The journey handles business API errors; a route-level React Error Boundary does not catch every network or event-handler failure.
